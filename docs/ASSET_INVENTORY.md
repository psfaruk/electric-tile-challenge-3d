# Asset Inventory — Electric Tile Challenge 3D

All assets in this repository are either **original works generated for this
project** or **CC0 public-domain photoscans** (v3.0 material pass). Licensing
risk mitigation: no restrictive-license third-party assets are shipped.

## Photoscan PBR library (v3.0, `assets/textures/pbr/*.webp`)

Real-world photoscanned PBR materials from **Poly Haven** (polyhaven.com),
licensed **CC0 1.0** (public domain — free for any use, no attribution
required; source and license documented here for transparency).

| In-game set | Poly Haven source | Maps | Resolution | Used for |
|---|---|---|---|---|
| `rubber_mat_*` | "Rubber Tiles" | albedo + normal + ORM | 2048² | studio rubber floor (arena, bleachers, menu floor) |
| `concrete_wall_*` | "Brushed Concrete" | albedo + normal + ORM | 2048² | upper studio walls |
| `steel_painted_dark_*` | "Blue Metal Plate" (desaturated to graphite) | albedo + normal + ORM | 2048² | wall wainscot, barriers, LED backboard, tile lips |
| `tread_plate_*` | "Metal Plate" (desaturated to neutral steel) | albedo + normal + ORM | 2048² | start/finish deck platforms |
| `curtain_stage_*` | "Velour Velvet" | albedo + normal + ORM | 1024² | stage entry drape |

Notes:
- ORM maps use Poly Haven's "arm" packing (AO=R, Roughness=G, Metallic=B),
  which is byte-identical to Godot's `orm_texture` packing.
- Normal maps are OpenGL green-up (`nor_gl`), matching Godot's convention.
- Conversion pipeline: 2K JPG (Poly Haven CDN) → hue-neutralization (baked
  once: metal plates desaturated) → WebP (albedo q85, normal q92, ORM q92).
  See the conversion rationale in the v3 commit message.
- Albedo tints (rubber ×1.45 lift, concrete ×1.55, painted steel ×1.6,
  tread ×1.25, curtain ×0.8 red) are applied in-engine via `albedo_color` —
  the shipped WebP sources stay faithful to the photoscan.
- The synthetic generators (`scripts-dev/gen_textures_pbr.py`,
  `gen_textures_human.py`) remain in the repo as regenerable fallbacks; the
  synthetic brushed-steel weave is still used for thin truss members (a
  photoscan reads scaled-wrong there — VLM art review).
- Texture import settings are committed per role (`.import` files): albedo =
  sRGB VRAM-compressed, normal = linear normal-encoded, ORM = channel-packed
  linear, all with mipmaps. Verified by `scripts-dev/probe_textures.gd`.

## Why procedural instead of Blender/GLB (and the upgrade path)

The plan requested Blender-authored GLB assets. This build ships a fully
procedural, original stylized asset set so that:

- every asset is reproducible from committed code (no binary provenance risk),
- the repository stays tiny and reviewable,
- the visual identity is consistent and tuned for mobile (emissive neon).

The gameplay/UI architecture is decoupled from the visual source. To adopt
Blender GLB assets later: export GLB models with animations, place them under
`assets/models/`, and replace the construction calls in `robot_model.gd` /
`arena.gd` with `AnimatedMesh3D`/`AnimationPlayer` instancing — nothing else
in the game needs to change.
